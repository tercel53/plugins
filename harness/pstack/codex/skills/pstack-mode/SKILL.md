# pstack 的 Codex 工作流

若入口经软链接安装，先用 realpath 或等价文件工具解析本 SKILL.md 的真实路径；本文所有相对引用均相对于真实文件目录，不相对于 .agents/skills 的链接位置。

先读 [Codex 适配约定](../../references/codex-adapter.md)。由当前会话承担任务责任，不委派另一个 Agent 执行整个入口。

## 明确范围

读取目标仓库 AGENTS.md 和命中任务的规范，检查现有改动。记录目标、文件范围、验收条件、工作区基线和证据位置。研究或规划请求只输出相应产物，不进入实现。yushu 任务再读 [项目接入](../../references/yushu.md)。

本入口负责 Bug fix 和 Feature。其他大型调度、自动合并、发布任务报告范围差异，不假装已覆盖。提交、推送、MR、外部写入遵守当前授权及项目规则。

## 理解与设计

按 [依赖索引](../../references/dependencies.md) 的 Codex 执行规则使用 how；缺陷追到可观察复现，必要时用 why 核对历史，区分事实与假设。

写代码先命名数据形状，读取 model-the-domain 原则。Feature 或跨函数边界的修复使用 architect / arena：取得两个独立结构候选，以行为覆盖、边界、复杂度和项目约束比较，选定后才实现。候选只需足够判断的类型、调用示例、草图，不要求两套完整业务实现。设计阶段已覆盖相同决策时复用结论，不重复竞赛；新出现的实现形状选择再运行 arena。

## 实现、验证和返修

1. 按已确认范围向实现子 Agent 传递目标、选定设计、命中文档、允许编辑路径和验收要求。多个写入者使用不相交路径或明确的隔离副本，不能把普通派生当成 worktree。
2. 有廉价回归路径时读取 [pstack-tdd](../pstack-tdd/SKILL.md)，先确认失败原因再修复。测试不适合时说明替代验证，不伪造红例。
3. 主会话检查实际 diff，执行任务所需验证层级。读取 prove-it-works 原则；证据记录被测版本、命令、结果与未运行项。
4. 读取 [pstack-review](../pstack-review/SKILL.md)，使用实现者之外的审查角色。把需求、固定 diff、上下文和证据交给它。
5. 核实有效发现。范围内阻塞项返回实现角色；改动后重跑受影响检查并复核发现。范围外问题保留后续项，不扩大修复。
6. 必需验证通过且阻塞发现处理完毕，才报告完成。缺环境、授权、独立审查能力或无法判定的需求，保留受阻原因和恢复点。连续修复不产生新证据时重查假设，不机械重复。

## 输出

给出用户可见变化、选定方案及理由、验证证据、审查处置和剩余限制。证据必须对应最终改动。局部测试、真实 API、UI 与远端门禁分别报告；当前任务有更高层级必需证据时，不能用低层级通过宣称完成。

上游方法见 [poteto-mode](../../upstream/skills/poteto-mode/SKILL.md) 的相关剧本；只按适配约定读取方法，不执行其自动提交、Cursor 工具和默认外部动作。
