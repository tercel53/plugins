# Codex 执行适配约定

## 使用范围

本包是 pstack 的 Codex 项目适配版。三个中文入口是执行规范，上游英文副本只提供方法、原则和模板；不原样执行其中 Cursor / Claude 专属命令、模型配置、自动提交或授权默认。

优先遵守用户范围、当前宿主指令与目标项目规则。选择 pstack 不改变其他任务的默认工作流。内部依赖用本包相对路径读取，不通过裸 tdd、teach 或 code-review 名称解析。

## 工具和角色

- 当前会话若提供 collaboration.spawn_agent / send_message / wait_agent，用这些工具委派、传递结果和等待；其他 Codex 会话只使用实际列出的子 Agent 接口。没有子 Agent 能力时，独立审查步骤受阻，不用创建用户侧栏聊天冒充子任务。
- 上游 Task、Agent、generalPurpose、poteto-agent 是角色意图，不是可直接提交的参数。实现角色接收明确路径、目的、允许操作、项目文档、证据要求和返回格式。
- comment-sicko 只作为注释审查的资料，不注册为会自动改文件的角色。审查 brief 明确只读，主会话核对修改；文字只读约束不等同于工具权限隔离。
- 不传 run_in_background、readonly、environment 等宿主未支持字段。文件附件用明确路径传递；消息或续接遵循实际工具语义。新修复轮次可用新实现角色携带汇总证据，只有确需保留活进程等状态时续用原角色。
- 当前宿主的并发上限就是上限。多个设计候选可以分批完成，再交叉审查。分批独立不等于并行，也不等于多模型。
- 读写代码用实际提供的 shell / patch 工具。Task 不是 shell 命令。TodoWrite 不可用时维护简短阶段记录。提问使用实际可用工具；确需用户决定的问题保留未完成阶段。

## 模型与隔离

默认继承当前模型，不复制 Claude / Grok slug，不改全局配置。仅在用户或适用指令明确指定且工具支持时覆盖模型。不同角色同模型要披露缺少模型多样性。用户要求真实多模型而宿主不支持时报告受阻，不偷偷降级。

子 Agent 默认可能共享检出目录。只读调查可共享；并发写入使用不交叉文件或显式隔离副本 / worktree。必要时使用当前宿主提供的 worktree 工具。文件隔离不隔离端口、数据库、凭证和远端夹具。

## 能力缺失与外部动作

control-ui / control-cli 映射到当前可用浏览器与命令工具。浏览器调用遵守该工具技能；没有真实页面访问能力就报告 UI 未验证。deslop 用项目静态检查和明确审查代替，不宣称完全等价。

首版不运行 Cursor Automations、Bugbot 启动、云 Agent、自动 shipping 或 PR babysit。必需步骤缺能力时标记 BLOCKED；只有不适用项可以说明理由后略过。不要照搬 Claude adapter 的占位符后继续交付规则。

Opening a PR 替换为本地可交付结果。是否 commit、push、MR、部署以及外部写入由用户和项目授权决定。不要执行原版 reset --hard、清理他人现场、默认开 ready PR 等规则。

## 按需加载和来源

每次应用原则，读完整叶子文件，只说明实际影响决策的原则。24 个原则不是 24 个子 Agent。按 [依赖索引](dependencies.md) 处理跨技能引用；返回 poteto-mode 的角色引用只读取本文件，不重启入口。

包内 upstream/ 为生成的完整来源快照，来源摘要见 provenance.json。不要手改生成文件；从仓库 pstack/ 更新后运行生成脚本。Codex 元数据仅注册三个入口，upstream 不放进技能发现目录。
